ProxyCraft 2.0.0 (Rust) — package notes

Layout:
- src/engine/: FFmpeg detection (caps.rs), probing and the proxy check (media.rs), command building
  (command.rs), output planning (plan.rs), the parallel batch engine (batch.rs) and process start-up
  (process.rs). No user-interface code; the window receives batch events through a channel.
- src/main.rs: egui/eframe window, dialogs and worker threads. src/theme.rs: Dark/Light colours
  (same values as 1.x). src/settings.rs: settings. src/help_text.rs: User Guide text.
- src/tools.rs: finding ffmpeg/ffprobe. tests/ffmpeg_engine.rs: end-to-end tests with real FFmpeg.
- ProxyCraft 1.x (Python/PySide6) is on the main branch; this branch is the Rust rewrite.

Encoding pipeline (chosen per file):
- NVIDIA (CUDA available and NVENC opens): -hwaccel cuda -hwaccel_output_format cuda, scale_cuda, then
  h264_nvenc / hevc_nvenc directly, or hwdownload + prores_ks for ProRes.
- Other GPUs (D3D11 decode works, CUDA pipeline does not): -hwaccel d3d11va -hwaccel_output_format d3d11,
  then hwdownload,format=nv12|p010le and CPU scale, then the normal encoder. Only for codecs in
  engine::command::D3D11_DECODABLE with 4:2:0 8/10-bit sources. Frames stay on the GPU until hwdownload, so a
  file the GPU cannot decode fails and is retried on the CPU instead of silently decoding in software.
  Detected at startup by encoding a short H.264 sample and decoding it the same way.
- Codecs the GPU cannot decode (ProRes, DNxHR, CineForm…) decode on the CPU. If GPU decoding fails for a
  file, it is retried on the CPU automatically.
- CPU path: scale with flags=area (fastest good filter for 2x/4x reductions in testing), then the first
  hardware encoder that test-opened (NVENC, Quick Sync, AMF) or libx264 / libx265.
- Every listed hardware encoder is test-opened at startup; FFmpeg builds list all vendors' encoders.
- Software fallback (engine::command::encode_attempts): the test only opens 8-bit 720p, so a hardware encoder can
  still fail on a file (10-bit, unsupported size…). After the GPU and CPU decoding attempts, H.264/H.265
  files get a last attempt with libx264/libx265 (if the build has them and they are not already the
  chosen encoder). Each failed attempt restarts the file; hardware encoders usually fail at open.
- Two files are encoded in parallel by default (fastest in testing on GPU and CPU).

Proxy properties:
- -noautorotate keeps the coded frame layout and the rotation flag, so proxies match originals.
- -fps_mode passthrough keeps every frame and timestamp; -map_metadata 0 keeps timecode.
- All audio tracks: copied when the container accepts them, else PCM (MOV) or AAC 192k (MP4).
- H.264/H.265: keyframe every second, no B-frames. H.264 8-bit 4:2:0; H.265 keeps 10-bit sources at 10-bit.
- Output is written to <name>.part and renamed on success; cancelled/failed files are deleted.

Build:
- Run build.bat on Windows with Rust 1.95+ (rustup, MSVC toolchain) and an internet connection.
- cargo build --release creates target/release/ProxyCraft.exe (thin LTO, stripped, panic=abort).
- build.rs embeds assets/ProxyCraft.ico and the version information (from Cargo.toml) in the EXE.
  The version is set only in Cargo.toml; build.bat and the installer read it from there.
- .cargo/config.toml links the Visual C++ runtime statically (+crt-static), so the EXE needs nothing
  but Windows 10/11. The window draws with wgpu (eframe's default renderer);
  release builds use the Windows GUI subsystem, so no console window opens.
- Settings: JSON in %APPDATA%\PitKub\ProxyCraft\settings.json (PROXYCRAFT_SETTINGS overrides the path,
  used by the tests). On the first start, the 1.x QSettings values in HKCU\Software\PitKub\ProxyCraft
  are imported.
- Third-party licences: after changing dependencies, regenerate licenses/RUST_CRATES.md:
    cargo metadata --format-version 1 --filter-platform x86_64-pc-windows-msvc | python scripts/crate_licenses.py > licenses/RUST_CRATES.md
- CI: .github/workflows/build.yml tests and builds on windows-latest and keeps ProxyCraft.exe.
- Tests: cargo test. The end-to-end tests need ffmpeg/ffprobe on PATH (or vendor/ffmpeg) and are
  skipped otherwise.

Proxy check:
- engine::media::compare_media compares source and proxy MediaInfo: frame count when both files store one
  (nb_frames), otherwise duration (1.5 frames tolerance, or 0.5 s when only the container duration is
  known); frame rate within 0.5%; timecode; audio track count; rotation; aspect ratio within 2%.
- ProxyBatch with BatchOptions.verify checks each Done and Skipped job and emits Event::JobCheck. The
  window's Tools → Check Proxies runs the same check on a worker thread without encoding.

Time left:
- engine::batch::TimeEstimator: work = frames x source pixels (decoding dominates and scales with frame size).
  Speed from the last 30 s of samples, starting at the first encoded frame; skipped/failed/cancelled
  jobs are excluded; existing proxies are marked Skipped before encoding starts. Lightly smoothed.
- Tested on a mixed batch (HD then 4K, 3 skipped, 1 broken): 19% average error vs 71% for the
  previous all-frames average.

Installer:
- installer/ProxyCraft.iss (Inno Setup 6), compiled by build.bat when ISCC.exe is found.
- Per-user install by default (no admin, %LOCALAPPDATA%\Programs\ProxyCraft); the first page offers
  all users (Program Files). The folder page is always shown. English and Polish.
- AppId {1BDF2899-8598-420E-8C23-CE263FD20CBF} must never change (upgrades and uninstall rely on it).

Included FFmpeg:
- get_ffmpeg.ps1 downloads one pinned BtbN FFmpeg-Builds release (GPL, shared DLLs), checks its SHA-256,
  and keeps ffmpeg.exe, ffprobe.exe, the DLLs and LICENSE.txt in vendor/ffmpeg. It also downloads the
  matching FFmpeg source and build scripts into vendor/release-sources for the GitHub release.
- build.bat copies vendor/ffmpeg to dist/ffmpeg and makes two ZIPs: with and without FFmpeg.
- Lookup order: a path the user chose in Settings (if the file still exists), then ffmpeg\ next to the
  EXE (vendor\ffmpeg when run from source), then PATH and C:\ffmpeg\bin. The included path is never
  saved, so moving the app folder keeps working.
- To update FFmpeg: change the pinned values at the top of get_ffmpeg.ps1, delete vendor\, rebuild,
  and update the version/commit lines in THIRD_PARTY_NOTICES.md and README.md.
